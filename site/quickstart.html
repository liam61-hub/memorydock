Quickstart

Run MemoryDock locally, point it at your own embedding provider, and share it with every agent on your machine.

MemoryDock is open source on GitHub. Install from source with the commands below. See the full installation guide for platform-specific MCP setup.

01

Before you start

⛭

Node.js 22 or 24 LTS, npm, and Git

Clone the GitHub repository, build a local package, and install it globally.

⚿

An embeddings endpoint

Any OpenAI-compatible API. Or a local Ollama model — zero external calls.

◷

About five minutes

Start the server, paste three blocks of config, ask your agent to remember something.

02

Pick your embedding provider

◉

OpenAI

The default. One key, one model, done.

Base URL https://api.openai.com/v1
Model text-embedding-3-small
Dimension 1536
◌

Ollama — zero external calls

Fully local. Nothing leaves your machine, ever.

Pull ollama pull bge-m3
Base URL http://localhost:11434/v1
Key ollama (any value)
Dimension 1024
⋯

Any OpenAI-compatible

together.ai, your company gateway, whatever speaks the protocol.

Base URL yours
Model yours
Dimension must match the model

The dimension must match your model. A mismatch is caught at startup with a clear error pointing you at the reembed command — see Changing models below.

03

Step 1 — Start the server

GitHub source 
git clone https://github.com/liam61-hub/memorydock.git
cd memorydock/server
npm ci
npm pack
npm install -g ./memorydock-2.0.0.tgz
Start 
memorydock init
memorydock doctor
memorydock serve

No MemoryDock account or token. The service binds to loopback and stores notes under ~/.memorydock. A hosted embedding provider may require its own API key.

04

Step 2 — Connect your agents

~/.claude.json (user scope) 
{
  "mcpServers": {
    "memorydock": {
      "type": "stdio",
      "command": "memorydock",
      "args": ["mcp"]
    }
  }
}
~/.codex/config.toml 
[mcp_servers.memorydock]
command = "memorydock"
args = ["mcp"]
default_tools_approval_mode = "approve"
startup_timeout_sec = 10
tool_timeout_sec = 60
Cursor → Settings → MCP 
{
  "mcpServers": {
    "memorydock": {
      "command": "memorydock",
      "args": ["mcp"]
    }
  }
}

Install globally and use the bare command. npx re-resolves the registry on every cold start — a known cause of flaky MCP connections.

Restart your client session after changing config. Use the client's MCP tool list to verify the connection.

Works with stdio MCP clients. The examples all launch the installed memorydock mcp command.

05

Step 3 — Verify

terminal 
curl http://127.0.0.1:40889/health

Then ask your agent:

Save something

"Save this to my memory: the staging deploy uses Node 20, not 22."

Recall it from another tool

"Search my memory for which Node version staging uses."

08

Changing embedding models

Switching to a model with a different dimension rebuilds every vector. Backup first, rebuild atomically — if it fails midway, your existing data is untouched.

terminal 
memorydock reembed --yes --backup   # backup to ~/.memorydock/backups, then rebuild
09

Where your data lives

▤

~/.memorydock/index

The rebuildable LanceDB search index — derived from your notes.

⧉

~/.memorydock/backups

Rolling memory-*.tar.gz backups, plus anything from reembed --backup.

⚿

~/.memorydock/notes

Canonical Markdown notes — the source of truth. Backing up is copying the folder. Erasing everything is deleting it.
